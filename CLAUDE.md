# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

NomadSafe is a travel safety and planning app built with Expo (SDK 57), React Native 0.86 and React 19.2, in strict TypeScript. It launches on Google Play first; iOS comes later.

## Commands

- **Install deps**: `pnpm install` (package manager is **pnpm**, not npm or yarn)
- **Start dev server**: `pnpm start`
- **Run on Android / iOS**: `pnpm android` / `pnpm ios`. These need a dev-client build; the app doesn't run in Expo Go.
- **Lint**: `pnpm lint`
- **Type-check**: `pnpm exec tsc --noEmit`
- **Tests**: `pnpm test` (node:test + esbuild: expense import/parser, expense splits/voice parsing, trip utils, AI money facts, sync hashing, exchange-rate cache rules, place opening hours, plans/trip limit, AI policy and provider adapters, ad frequency rules, invite link parsing, trip recap, day shape (durations, moves, free time, meals, leave-by, travel details from booking text), passport and border views, passport MRZ lines, your-spend and recurring dates, receipt text, Splitwise/Settle Up import parsing against anonymised exports in `tests/fixtures/import`, saved ideas and save targets, shared links and place detection, planned-trip sharing, replay photo curation, stop schedule/nights/highlights/walking days, distance comparisons, replay chapters and the shared-video timeline, location broadcast policy, perf tiers, storage write coalescing, forex pockets)
- **i18n check**: `node scripts/check-i18n-keys.mjs`
- **Backend**: `npx convex dev`
- **Release**: see `docs/PLAY_RELEASE.md` (EAS profiles are in `eas.json`)
- **Website**: `website/` (Vite + React, prerendered; its own pnpm root and lockfile, excluded from the app's tsc/eslint). See `website/README.md`; deployed as the `nomadsafe-site` Cloudflare Worker (static assets + `website/worker/index.ts`) by Workers Builds from Git

## Architecture

The code is split into three layers. ESLint (`no-restricted-imports` in `eslint.config.js`) enforces the boundaries.

- **`src/atoms/`**: generic, reusable UI primitives (Aura buttons, fields, lists, chips, `AuraSheet` (the one bottom sheet), `AuraOptionSheet`, `AuraAlert` (`showAlert` / `showToast`, which replace the native `Alert`), motion helpers, icons, tab bar, `AuraSkeleton` (shimmer placeholders for loading content; keep spinners for button/action progress) and `AuraEmptyState`). Design tokens (`auraSignal` colours, `auraType`, `auraSpace`, `auraRadius`, `auraHitSlop` for icon buttons under 44 pt) live in `src/constants/aura.ts`. Import them from `@/atoms`, never deep paths. Only generic primitives belong here; components with feature knowledge stay in their feature.
- **`src/modules/<name>/`**: infrastructure, each the single source of truth for one concern and the only place its SDK is imported. Import from `@/modules/<name>` (its `index.ts`) only.

  | Module | Owns | Wraps |
  |---|---|---|
  | `ai` | All AI: `aiService` (chat + structured tasks), model download/lifecycle (`aiRuntime`), your-own-key config, availability hooks. **`policy.ts` decides which providers each task may use, and in what order**; change AI behaviour there | llama.rn, provider APIs, the Convex cloud endpoint |
  | `backend` | Convex client, `api`, React hooks (`useQuery`/`useMutation`/`useAction`), `BackendProvider`, Better Auth client, JWT exchange and HTTP client for background tasks | `convex/*`, `@convex-dev/*`, `@convex/_generated` |
  | `billing` | RevenueCat, plan store and rules (`usePlan`, `useStartNewTrip`, `FREE_TRIP_LIMIT`), `BillingEffects` | `react-native-purchases` |
  | `ads` | AdMob interstitials at natural breaks (`showInterstitial(placement)`; free plan only), shared frequency rules in `rules.ts` (tunable through the `ad_frequency` PostHog flag payload), UMP consent, `AdsEffects` | `react-native-google-mobile-ads` |
  | `analytics` | PostHog events, flags, session replay, `<PrivateView>` (hides content from recordings) | `posthog-react-native` |
  | `logger` | Logging (`logger`) | PostHog Logs |
  | `storage` | Encrypted MMKV (`storage`, `mmkvStateStorage`), `secureStore`, `credentials` (keychain) | `react-native-mmkv`, `expo-secure-store`, `react-native-keychain` |
  | `appCheck` | Firebase App Check tokens for billed backend calls (`getAppCheckToken`, `withAppCheck(args)`); Play Integrity on Android, debug provider in `__DEV__`, skipped on iOS until Firebase is configured there | `@react-native-firebase/app`, `@react-native-firebase/app-check` |
  | `notifications` | Permissions, channels, local notifications, push token, tap handling | `expo-notifications` |
  | `location` | Permissions, positions, geocoding, background updates (`defineLocationTask`), `MapView`/`Marker`/`Polyline` (react-native-maps is loaded lazily so headless tasks stay light) | `expo-location`, `react-native-maps`, `expo-task-manager` |
  | `health` | Read-only steps and walking distance for a date range (`health.availability`, `requestAccess`, `readWalking`, per-day `readDailySteps`); Android also asks for history (older than 30 days) | `react-native-health-connect`, `@kingstinct/react-native-healthkit` |
  | `display` | Asking an adaptive-refresh Android screen for its top rate (120 Hz) during fast animations (`setHighFrameRate`; the tab bar's lens uses it, and resets it when it settles), and hiding the app's recents screenshot while the app lock is on (`setRecentsPreviewHidden`, Android 13+) | local `modules/expo-frame-rate` (`preferredRefreshRate`, `setRecentsScreenshotEnabled`) |
  | `photoCurator` | On-device photo labels and quality scores for picking a trip's best photos (`photoCurator.analyze`; `isAvailable` false on older builds, where curation uses dates and places only) | local `modules/expo-photo-curator` (Vision `VNClassifyImageRequest`, text recognition and iOS 18 aesthetics; ML Kit image labelling, bundled model, and text recognition) |

  To swap a vendor, change only its module. Modules may import other modules and feature stores; features never import a module's internals.
- **`src/features/<name>/{screens,components,hooks,services,store,utils}`**: product features (screens, feature components, stores and feature logic). `src/app/` route files are thin re-exports of feature screens. App-wide helpers that aren't infrastructure live in `src/constants` (design tokens, legal URLs), `src/utils`, `src/hooks` and `src/providers`.
- **Android glass blur**: `patches/expo-blur@57.0.3.patch` swaps Dimezis' RenderNode controller for `CroppedBlurController`, which blurs only the area behind each BlurView at 1/4 size (the stock one blurs the whole screen at full size every frame, which kept the tab bar off 120 Hz). Keep it on expo-blur upgrades.
- **Local native modules** (`modules/*`): each `expo-module.config.json` needs `apple.podspecPath`, because the podspec sits at the module root and Expo's autolinking only looks in subfolders; without it the pod still builds but the module is never registered on iOS (`requireOptionalNativeModule` returns null).
- **Entry**: `index.ts` imports the background-task files (`features/location-sharing/services/locationBroadcastTask`, `@/modules/ai/background`) and registers the Android widget handler before `expo-router/entry`, so Android can run them on a headless launch. New background tasks must be imported there, through a light entry file rather than a whole module.
- **Routing**: Expo Router.
  - `src/app/_layout.tsx` contains the providers, `ErrorBoundary` (reports to PostHog), `AppStateLock` (auto-lock timer), `LockGate` (the optional app lock, an RN `Modal` over every route), `SessionEffects`, `BillingEffects`, `AdsGate`/`AdsEffects` and `AuraAlertHost`.
  - `AuraAlertHost` is mounted last so dialogs show above the lock screen.
  - **App lock**: off by default; Settings → App lock turns it on (`authStore.lockEnabled`). There is no app PIN: it unlocks with the phone's own screen lock through the system prompt (`localAuth.authenticate`: biometrics, with the phone's PIN/pattern/passcode as the fallback; strong biometrics on Android 11+). Turning it on or off asks for that prompt; it needs a phone screen lock, and if the phone's screen lock is removed later the app lock turns itself off at the next unlock. PINs from older versions are deleted by the auth store's v2 migration (`removeLegacyPin`), which also turns the lock off. On iOS, `LockGate`'s modal also carries `PrivacyCover` while the app is inactive/backgrounded (app-switcher snapshot); wrap calls that open system UI (Face ID, permission, purchase, sign-in sheets) in `withSystemPrompt` (`src/utils/systemPrompt.ts`) so the cover doesn't flash over them; with the lock on, Android 13+ also hides the recents screenshot (`setRecentsPreviewHidden` in `@/modules/display`, set by `RecentsPrivacy` in the root layout).
- **Path aliases**: `@/` → `./src/`, `@convex/` → `./convex/`.
- **State**: zustand stores persisted to **encrypted MMKV** (`@/modules/storage`: AES-256, with the key in the Keystore/Keychain). No other MMKV instances. Writes are coalesced (300 ms, foreground only; direct in background/headless) and flushed on background; call `flushPendingWrites()` before reading stores for a ledger or clearing, and `clearAllStorage()` to wipe. Use batch actions (`updateExpenses`, `removeExpenses`, `addSettlements`, `updateEvents`) instead of per-item loops. Exchange rates live in `ratesStore`. Stored Gmail text is cut to 2,000 characters; saved chats keep the last 200 messages per conversation. Storage fails closed: if the key can't be read or saved (Keystore error, iOS before the first unlock), the session runs on in-memory storage (`isStoragePersistent` is false), never opens the file without its key, and reloads once the keychain answers. A new key is generated only when the keychain reports none exists. Keychain items are `*_THIS_DEVICE_ONLY` (the session cookie and MMKV key are readable after first unlock, for background location).
- **Backend**: Convex + Better Auth (Google sign-in only).
  - `convex/users.ts`: auth helpers; user lookups go through the Better Auth component.
  - `convex/sharing.ts`: contact links, invites, location shares. A share shows until its `endsAt` (sent by the phone); shares with no end, and SOS, hide after 48 h without an update, since phones publish only when they move.
  - `convex/account.ts`: account deletion. It also schedules `convex/analytics.ts` to delete the user's PostHog data (needs `POSTHOG_PERSONAL_API_KEY` and `POSTHOG_PROJECT_ID` Convex env vars).
  - `convex/legalPages.ts`: `/privacy` and `/delete-account` pages. They and `/join` are served on our own domain (`EXPO_PUBLIC_WEB_URL`, Convex `WEB_URL`) by the website's Worker (`website/worker/index.ts`), which forwards only those paths; Google sign-in, AI and the RevenueCat webhook stay on the Convex site URL. The app still accepts invite links on the Convex site.
  - `convex/groups.ts`: shared groups and trips (a trip is a group with travel details): `sharedGroups`, `groupMembers`, `groupRecords`, invite codes, membership checks; `convex/pushNotifications.ts` sends Expo pushes for money changes and stores `pushTokens`. `/join/<code>` (in `legalPages.ts`) opens `nomadsafe://join/<code>`.
  - `convex/safetyAlerts.ts`: SOS / missed check-in pushes to the user's accepted `contactLinks` (the people who get their live location). The app mirrors the check-in deadline with `setCheckIn` (`features/safety/services/safetyServerAlerts.ts`, from `useSafetyServerSync`); a scheduled job alerts contacts 5 min after it passes. Clearing or moving it after an alert, and `resolveSos`, send an "is safe" push.
  - `convex/billing.ts`: the `entitlements` table, filled from the RevenueCat REST API by the webhook (`/revenuecat/webhook`) and `refreshMyPlan`. `planGrants` give a plan without a purchase (review account, testers: `grantPlanByEmail` / `revokePlanByEmail` / `listGrants`); an hourly cron deletes expired ones, since queries don't re-run as time passes. Pure plan/quota rules are in `convex/billingRules.ts`.
  - `convex/ai.ts`: Pro cloud AI through OpenRouter (`OPENROUTER_API_KEY`; the model comes from `CLOUD_AI_MODEL`, default `openai/gpt-6-luna`; only providers that don't collect data). `complete` (structured tasks) and the streamed `/ai/chat` HTTP action check the plan, a rate limit and the monthly `aiUsage` quota; the client passes the task id, and `aiUsage.byTask` keeps per-feature counts (never content) for `myUsage` and the Settings usage sheet. The phone keeps its own log of online AI uses (feature, provider, time) in `src/modules/ai/usageLog.ts`, cleared on sign-out/wipe.
  - `convex/weather.ts`: MET Norway weather (free, commercial OK, credit "MET Norway" in Settings). each 0.1° cell's summary (daily forecast + next 24 h, ~2–3 KB) is cached in `weatherCells` until MET's `Expires`. The app reads it through the `cell` query (Convex-cached across users) and calls the `refresh` action only when it's missing or expired (signed-in only, per-user rate limit, `If-Modified-Since` from the app's copy). Cells are kept at least 3 h and the phone keeps each place 6 h (`getPlaceWeather`); the globe badge reads current conditions from the stored hourly outlook. This is tuned for the Convex free plan (~25 calls per active user per day): keep a cache miss to three function calls; `refreshGlobeClouds` (hourly cron in `convex/crons.ts`) fills the `globeClouds` grid the globe subscribes to. Parsing/aggregation is pure in `convex/weatherRules.ts`. Phones never call a weather API directly, so upstream traffic grows with places, not users. Set the `SUPPORT_EMAIL` env var (MET requires a contact in the User-Agent).
  - `convex/rates.ts`: shared exchange-rate cache (`exchangeRates`, one row per pair and requested day), the same pattern as weather: the `rate` query (Convex-cached across users), then the `refresh` action from Frankfurter on a miss (signed-in only, per-user rate limit). Days before yesterday (UTC) never expire; recent ones last 6 h; rows are pruned 90 days after fetching (cron). Rules are pure in `convex/ratesRules.ts`. The phone (`features/expenses/services/currencyConversion.ts`) checks its own copy first, then the server, then Frankfurter directly (signed out or server down), then the nearest stored rate.
  - `convex/sync.ts`: trip backup (`syncRecords`, last-write-wins by `updatedAt`, per-user `serverSeq` pull cursor, tombstones for deletes).
- **Trip backup**: `features/sync/services/syncEngine.ts` syncs trips, groups, expenses, settlements, itinerary events and recurring rules to the account while signed in with `cloudBackupEnabled`. It diffs the stores against a per-user ledger in MMKV, so store actions don't need sync hooks. `rawText` and the `note` of email imports (sender, subject, body) never leave the device (`stripRaw` / `keepLocalOnly` in `features/sync/utils/sharedScope.ts`, used by both engines). Sign-out clears backed-up data from the phone; data from another account is cleared on sign-in, unowned data is adopted. Stop the engine before resetting those stores, or the reset is pushed as deletions.
- **Groups and trips**: a group (`Group`, `kind: "group"`) has people, a currency and expenses; a trip (`Trip`) is a group with travel details. The trips store keeps `trips` and `groups` as two lists, so trip code never sees a group; money code reads both through `selectMoneyGroups` / `findMoneyGroup`. Expenses and settlements point to `groupId` (null when in no group); itinerary events keep `tripId`. Only trips can be the active trip. Free covers 2 owned trips and 2 owned groups (`canCreateGroup`, `useStartNewGroup`).
- **Money tab** (`features/expenses/screens/ExpensesScreen.tsx`): the active trip's money, else the Overview (`MoneyOverview`: your week/month spending everywhere, where it went, overall balance, trips and groups with settled ones folded, spends with no trip or group, called "Personal"), titled "Money", with a chip row of trips and groups under the title and a period picker ("October ⌄": this month, this year, past months and past years with data, each with its total). A trip or group has a "‹ Overview" back link and its name as the `MoneySwitcher` (trips and groups only, never the Overview), which opens another without changing the active trip (`moneyViewStore`). The header's only button is ⋯ (`MoneyActionsSheet`: record payment, people, settings, import, export). When everyone is settled, balances shrink to one "All settled up with N people" line. Plus insights (`SpendCharts.tsx`, `SpendInsights.tsx`, pure math in `utils/spendInsights.ts`): a started trip shows your daily pace against its budget, where you'll land and what's left per day, over a strip of days (bookings before the start count toward the total, not the pace); a group shows where it spends once places repeat; the Overview has a sparkline (six months, or the year's months) with the month against your usual (the average of up to 3 earlier months since your first spend) or the year against last year plus its monthly average, categories against the same, a weekend vs weekday line (last 90 days, current period only) and your biggest spends as a sideways row of info-only cards (amount, name, trip or group, date). A trip or group (`GroupMoney`) shows balances first when it has people (`GroupBalances`, `useGroupBalances`), your spend, then activity by day with "you lent / you borrowed". "Your spend" counts your share of split expenses and the whole of unsplit ones, never settlements (`utils/myMoney.ts`, pure). The add sheet has an "In" picker (also moves an expense) and a Paid by / Split / With summary over `SplitEditor`. Groups are created in `NewGroupSheet` (behind `useStartNewGroup`); people and sharing are in `GroupPeopleSheet`; `GroupSettingsSheet` has name/emoji, smart split (`smartSplit`, default on, shared with members; off shows pairwise debts from `pairwiseDebts`), archive (only when settled up; `isArchivedGroup`: `shared.archived` per member, else the local `archived` flag; archived ones sit in an Archived fold on the Overview and the Trips tab) and leave/delete (`useRemoveGroup`).
- **Shared groups**: `features/sync/services/groupSync.ts` mirrors `groups.myGroups` (a live Convex subscription) into the trips store (`shared`, local id `g-<serverId>`; shared details carry `kind: "group"` for groups) and syncs each one's group expenses (split, or paid by someone else), settlements and itinerary. Splits use member ids on the server and `SELF_ID`/member names locally; names are unique per trip and never renamed. Unsplit expenses on a shared trip stay in the personal backup. Invite links are held in `pendingJoinStore` until the user is in the app. Deferred invites (link opened before install) come through `features/trips/services/deferredInvite.ts`, once per install and before onboarding: the Play install referrer (`join=<code>`, added by the `/join` page) on Android, the invite URL the page copies to the clipboard on iOS (needs the `IOS_APP_STORE_URL` Convex env var). Archiving is per member; owners can delete only after everyone who joined is removed; members leave only when settled up.
- **Destination search**: `features/trips/components/DestinationSearch.tsx` matches the bundled GeoNames cities, countries and curated popular places (`features/trips/data/cities.ts`, generated by `scripts/build-destination-cities.mjs`; never edit by hand) and, when fewer than 3 match, adds Google Places suggestions through `convex/places.ts` (`autocompleteDestinations` / `resolveDestination`, one session token per search so it is billed as one Place Details call). Show the "Google Maps" credit whenever Google results are on screen. `geocodeDestination` checks search picks, then bundled coordinates, then Google.
- **Must-dos**: the best-known sights near the top 400 destinations ship in `features/itinerary/data/mustDos.ts`, generated by `scripts/build-must-dos.mjs` from Wikidata (CC0, ranked by Wikipedia sitelinks; never edit by hand). `mustDosNear` (`features/itinerary/utils/mustDos.ts`) picks the nearest destination's list, named in the app language where we have one. They're offered on the Trip prep card before a trip (save to the wishlist) and on free days (add to that day); dismissals are per trip in `mustDoStore`, on the phone only.
- **Tickets**: files attached to itinerary items (booking PDFs from Gmail, PDFs/images from the file picker, photos from the system picker) live only on the phone: `ticketsStore` (separate from the events, so they can never sync) plus files in `documentDirectory/tickets/` (`features/itinerary/services/tickets.ts`). The trip Gmail sync saves the PDF attachments of the emails behind each booking (≤10 MB, deduped by message + file name). They open in `/ticket/[eventId]` (`react-native-pdf`, images with pinch zoom) at full brightness (`expo-brightness`); the page stays white for gate scanners while the screen around it follows the theme, behind `PrivateView`. Deleted with their item or trip (`pruneTickets`), on sign-out and on wipe. Each ticket lives in its own folder under its real name, so a sent copy reads "boarding-pass.pdf". **Group tickets:** files never sync; on a shared trip only a label does: the item's `ticketHolders` (member ids on the server, `SELF_ID`/names locally, kept in step by `syncTicketHolder` while this phone has a ticket marked "Visible to the group", off by default for flights). Others get it from the holder through the share sheet (`sendTicket`) and "Open with NomadSafe" (Android `VIEW` intent filter for PDFs/images, iOS `CFBundleDocumentTypes`): `+native-intent` stores the content/file link in `incomingTicketStore` and `/receive-ticket` asks which item it belongs to. "Ask for it" is `groups.askForTicket` (holders only, one per item per person per 30 min), a push that opens the ticket on the holder's phone.
- **Trip at a glance and day view** (`docs/TODAY_ITINERARY.md`): before the trip, Home's day rail is the summary (tick height = how full each day is, `DayRail` `levels`) and the picked day shows in `GlanceDayCard` under it (headline, tonight's stay, distance, free time, what's missing, first items; `useTripGlance`); during it, the day plan (`DayPlan`, drawn as a timeline: a line with an icon per item) adds how long each item takes (`~` when guessed from the title, the trip's usual or the type), getting out of the airport, being at the airport/station early, the move to the next item (straight-line estimate × 1.3: walk, transit or car; never a directions API), free windows of an hour or more and lunch/dinner with nothing planned (per-country meal windows in `data/mealTimes.ts`, shifted to the trip's own meal times), and "Add place / Add ticket" chips; tapping a free window opens `GapSheet` (saved ideas close by and Google nearby places open then, each addable). All of it is pure in `utils/dayShape.ts` (`tests/day-shape.test.mjs`). `/trip-plan/[id]` (`TripPlanScreen`, "All days" on the DayRail, "Full plan") stacks every day under a real map (`TripPlanMap`; the trip's cities until items have places) that shrinks as you scroll and follows the day in view, with the same `DayRail` as Home to jump between days. Items get a place once: `useItineraryPlaces` looks up placeless items by `where` or title near that day's stop (`convex/places.ts` `findItineraryPlaces`, batched, own `itinerary` rate limit) and saves `place` on the item (it syncs); `placeLookupStore` remembers what was tried. Transit items carry `travel` (terminal, gate, platform, coach, seat, boarding time) from the booking text (`utils/travelDetails.ts`, Gmail import and screenshots) or the form; `TravelDayCard` shows them with "Leave by" (`travelPlan`), and `services/travelReminders.ts` schedules "Leave by" / "Boarding soon" local notifications only when notifications are already allowed. No live flight or train status. A ticket screenshot can create an item: `readTicketScreenshot` reads it with `@/modules/ocr` and the Gmail parsers (`bookingsFromText`), on the phone only, and keeps it as the item's ticket. The item form also has "Where", an end time for any item and a booking link.
- **Saved ideas, planned trips and sharing in** (`docs/SAVED_IDEAS.md`):
  - **Ideas:** a trip's ideas are wishlist itinerary events (`timing: "wishlist"`, plus optional `savedBy`, `place` and `link`). They show in "Before you go", the Saved sheet (`SavedIdeasSheet`, mounted once in the root layout and opened through `savedSheetStore`), under each day's plan (`DayIdeas`) and at the top of the full itinerary. They never show with a time.
  - **Planned trips** are a separate `plannedTrips` list in the trips store, so nothing that needs dates ever sees one. Confirming one (`confirmPlannedTrip`) turns it into a trip with the same id. The free plan gets 3, and the 2-trip limit applies on confirm. Group sync works on `selectShareables` / `setShareables`; a planned trip's shared details say `kind: "planned"`, and only the owner can confirm.
  - **Sharing in:** links from other apps arrive through the iOS Share Extension (`targets/share`, which opens `nomadsafe://save-link?...`) or Android's share intent (`expo-share-intent` with `disableIOS`, `AndroidShareIntake`). They wait in `incomingShareStore` until the user is in the app, then `/save-link` opens. Place detection (`findPlaceInText`) and the choice of trip (`saveTargets`) are pure. Previews come from YouTube/TikTok oEmbed and Open Graph tags (never Instagram, which shows them only to Meta's crawlers). Reels and videos play in `/idea/[eventId]` (`react-native-webview`). A frame captured from an Instagram reel stays on the phone in `ideaThumbsStore`.
- **Back of the trip pass** (`usePassBack`, `home/components/aura/PassBack.tsx`), by stage: before the trip, the destination's time difference (Places `utcOffsetMinutes` from the safety search), currency (`¥10,000 ≈ $63`, local currency vs the user's), plugs (with "bring an adapter" against the home country) and emergency numbers; during it, tap-to-call local numbers, the nearest real hospital (Places `primaryType`) to you, the home embassy on international trips and the stay with **Show to driver** (`DriverCard`: name and address in the local language via `places.localAddress`); after it, the trip's numbers and replay. Country facts (emergency numbers, plug letters, volts, language, currency) are bundled in `features/trips/data/countryFacts.ts`, generated by `scripts/build-country-facts.mjs` from Wikidata (CC0; never edit by hand; small overrides in the script). The embassy comes from `places.embassyFor`: one Google lookup per pair of countries, shared by everyone in the `embassies` table for 30 days; the phone keeps embassies and driver addresses in `travelInfoStore` for offline use (cleared on sign-out and wipe).
- **Globe imagery**: day/night (real sun and moon) and cloud motion are computed on the phone; the cloud cover comes from `api.weather.globeClouds`. Whole-globe textures are bundled; sharp regional imagery (`features/home/services/globeImagery.ts`) stitches NASA Blue/Black Marble tiles from our Cloudflare R2 copy (`EXPO_PUBLIC_GLOBE_TILES_URL`, filled once by `scripts/mirror-globe-tiles.mjs`), falling back to NASA GIBS, and keeps each box in the documents directory (pruned once per session: unused 60 days or past 100 MB; cleared on wipe). Phones with 4 GB of RAM or less use 2x2-tile boxes (`GLOBE_MAX_TILES`). The route box and today's stop box are on screen; other stops are prefetched.
- **Trip recap**: `features/recap`. When a trip ends: a 10:00 next-day local notification (`services/recapNotifications.ts`; scheduled only if notifications are already allowed), a Home card, and the full-screen replay (`/trip-recap/[id]`). Opening it (from anywhere) first shows **Make it yours** (`components/replay/PrepScreen.tsx`; done or skipped once per trip, `recapStore.prepped`): photos and steps, each behind an `ExplainSheet` (`hooks/useRecapExtras.tsx`), then Play; the replay itself never stops to ask. Chapters (`utils/replayChapters.ts`, pure; split into `components/replay/`): intro, one per stop (the leg draws, then the arrival: board code, how you got there, nights from `utils/replayFacts.ts` `stopSchedule`; then up to 3 photos full-bleed with Ken Burns while the map shrinks into a corner inset, with that stop's itinerary highlights and biggest walking day), distance (by mode, with a comparison from `compareDistance`), countries (first visits and "Country #n" from the passport), companions (only with companions or shared members), numbers, the stamping moment and the finale (the pass with an "Edit photos" chip, one "Share your trip" button opening a sheet with Story image / Video and the spend toggle, then "Plan next trip" and, only while balances are unsettled, "Check balances"; the X closes it). Tap right/left for next/previous, hold to pause; reduce motion turns off Ken Burns and camera moves. Motion is calm: entrances use `rise()` in `components/replay/replayStyles.ts` (fade + 10 dp rise, no overshoot); springs only for the stamp slam and the departure board. Legs with no booking of 700 km or more count as "Likely flights" in the distance breakdown (`LIKELY_FLIGHT_KM`); the map still draws them as unbooked. Music: two CC0 FreePD tracks in `assets/audio/recap-*.m4a` (credits in `assets/audio/CREDITS.md`) via `expo-audio` (`hooks/useReplayMusic.ts`): fades, pauses with the replay, silent with the iPhone ring switch off, mute remembered in `recapStore.muted`. The replay is a flat Skia map; country outlines come from `data/countryShapes.ts`, generated by `scripts/build-country-shapes.mjs` from Natural Earth (never edit by hand), and also give each stop's country. The share card is drawn with Skia on a CPU raster surface (`components/recapCard.ts`), never a second GPU canvas, and Home drops its globe while the replay is open (`replayOpen`). Trip numbers are pure in `utils/recapFacts.ts`, map framing and label placement in `utils/recapMap.ts`. Spend goes on the card only when the user turns it on; there is no money chapter. **Share as video**: a ~15–20 s cut of the replay planned by `planVideo`/`videoFrameAt` in `utils/cardTimeline.ts` (pure; route with labels, up to 2 photos per stop, the numbers, then the card building itself and holding; its final frame is the static card), drawn by `components/recapVideo.ts` frame by frame on a raster surface and encoded to a 720×1280 H.264 MP4 by the local native module `modules/expo-video-encoder` (AVAssetWriter / MediaCodec), which also muxes the replay's music as AAC with a fade-out (`finishWithAudio`; builds without it share a silent video); the button hides when the module isn't in the build. Transit itinerary events carry an optional `transitMode` (guessed from the text for older events); route ends written as airport codes are placed with the bundled `features/itinerary/data/airports.ts` (OurAirports, generated by `scripts/build-airports.mjs`, never edit by hand). **Steps** come from `@/modules/health` (totals and per-day steps) and are cached per trip in `recapStore.walking` (read again until 3 days after the trip, as health apps sync late). **Photos** come from the system picker only (up to 100 at once, `services/tripPhotos.ts`); the phone labels and scores them, including how much of each is text (`@/modules/photoCurator`) and `utils/photoCuration.ts` (pure) drops ones from outside the trip dates and ones that aren't moments (food close-ups, roads, screenshots, receipts, documents), keeps the best of each burst and up to 3 per stop (24 in all) spread over days, placed by EXIF GPS, else by the day (`stopOnDay`). Only the chosen ones are kept (shrunk into `documentDirectory/trip-photos/`, `tripPhotosStore` with their stop; paths are re-pointed at the current documents folder on load, since iOS moves the app container on updates); the other picks stay for the session as swaps in `PhotoEditorSheet` and their temporary files are deleted when the replay closes. Neither steps nor photos are backed up or uploaded, and neither goes on the share card image; both are cleared on trip delete, sign-out and wipe.
- **Passport**: `features/passport` (`/passport`, the "Your passport" card in Trips, Settings → Home country). Stamps and state seals are worked out on the phone (`utils/passport.ts`, pure) from trips and past travel; nothing is stored per stamp. Countries other than the home country (`useHomeCountry()`: Settings, else the phone's region) get one stamp per country per trip; stops at home light up states, found with the bundled outlines in `data/regionShapes.ts` (generated by `scripts/build-region-shapes.mjs` from Natural Earth admin-1, never edit by hand; over-fine countries such as France and the UK are grouped into regions). Past travel (`passportStore`) is backed up as sync kind `passport`. The replay has a stamping chapter before the finale. The passport is a book (`components/PassportBook.tsx`) that opens closed on its Skia leather-and-foil cover (`PassportCover.tsx`), which swings open about the spine; pages then turn with a drag or an edge tap as a Skia page curl (`utils/pageCurl.ts`): during a turn one canvas draws the turning page and the page beneath from `makeImageFromView` snapshots of the open page and its neighbours (taken at rest, retaken when `contentKey` changes) over the untouched live pages, with a CC0 page sound (`assets/audio/CREDITS.md`) and a haptic on landing. Inner pages are light security paper (`PassportPaper.tsx`); the data page shows the Google photo (phone only, never uploaded), a passport number hashed from the user id and an MRZ (`utils/mrz.ts`, `tests/passport-mrz.test.mjs`); stamps and seals are scattered by id (`utils/scatter.ts`). **Borders:** people whose phone region or home country is India see India's official borders (Ladakh and Jammu and Kashmir as India shows them, with those areas taken out of Pakistan and China: `COUNTRY_SHAPES_IN_VIEW` / `REGION_SHAPES_IN_VIEW`, built by the same scripts with mapshaper). Everyone else sees Natural Earth's default. The view lives in `features/recap/utils/boundaries.ts` (set by `useBoundaryViewSync`); every outline and country/state lookup goes through it, so never read the shape tables directly.
- **Background location**: `features/location-sharing/services/locationBroadcastTask.ts` (a `defineLocationTask` from `@/modules/location`) picks a profile with the pure rules in `utils/broadcastPolicy.ts`: walking (balanced, 60 s), driving (30 s), low battery (5 min), still (after 5 min within ~50–150 m: a 150 m geofence and low-accuracy updates; leaving it switches back), SOS (high accuracy, 15 s; 60 s when still). It skips publishes inside the fix's accuracy unless a 10 min heartbeat is due, drops fixes worse than 500 m, backs off on failures and skips when offline; a 15 min `expo-background-task` watchdog (registered only while sharing) enforces expiry and the idle stop when no fixes arrive. The JWT is cached in encrypted MMKV; `getBackendHttpClient` is a single shared client. It gets a Convex JWT and an HTTP client from `@/modules/backend` and calls `sharing.publishLocation`. Its state is kept under its own MMKV key, not the UI store.
- **Plans**: Free (2 owned trips and 2 owned groups; joined ones don't count), Plus (unlimited trips and groups, plus money tools behind `usePlusGate`: shares splits and saved splits, recurring spends, the spending charts and insights, CSV/PDF export, receipt scanning; monthly, yearly or lifetime) and Pro (Plus + cloud AI, including split-by-item receipts), sold through RevenueCat (`@/modules/billing`; the paywall UI is `features/billing`). The app gates on RevenueCat's cached `CustomerInfo` (`planStore`); start new trips through `useStartNewTrip()`. Paid plans are ad-free; the free plan gets AdMob interstitials after finished actions (`showInterstitial` from `@/modules/ads`; never on safety, voice or lock screens). `EXPO_PUBLIC_REVENUECAT_TEST_STORE_KEY` (RevenueCat Test Store) replaces the store key in development (`__DEV__`) builds only; the SDK closes release builds that use it. See `docs/MONETIZATION_PLAN.md`.
- **AI**: features call `aiService` from `@/modules/ai`, never a provider directly. `src/modules/ai/policy.ts` (`AI_TASK_ROUTES`) gives each task its providers in order: today the user's own key (direct from the phone, key in SecureStore), then NomadSafe Cloud (Pro), then the on-device model. `expenseCategory` and `itinerary` (Refine, which only tidies Gmail-imported bookings and never removes what the user added) are on-device only, because Gmail and SMS text must never go online. Online AI also requires Settings → Online AI and a connection. Prompts and output parsers are in `prompts.ts`, JSON schemas in `schemas.ts`. Only the on-device chat prompt may say replies stay on the phone.
- **Home and launch without a trip**: Home keeps the globe and adds `EverydayCards`: your balance across groups (`useOverallBalance`, opens the Money Overview) and "Get home safe" (asks the Safety tab to open the safe-arrival sheet through `safetyIntentStore`). `useLandingTab` (in the tabs layout) picks where a new session opens (launch, or back after `SESSION_TIMEOUT_MS`): Home during a trip; otherwise Money once 2 sessions in a row visited it, and Home again after 2 sessions that left it within 5 s unused (`utils/landing.ts`, pure). It only moves off Home, so links and notifications win.
- **Forex pockets** (Plus; `features/expenses`: `utils/forex.ts` pure, `services/forexPockets.ts`, `store/pocketsStore.ts`, `TripForex`/`AddForexSheet`/`PocketSheet`): forex cash or a forex card for a trip. Loading it is a transfer, never a spend; the markup over the day's market rate is a "Fees & forex" spend (category `fees`). Spends paid from a pocket (the add sheet's "Paid with" row, or voice "paid cash") deduct your paid part and convert at the pocket's weighted market rate into its home currency (`pocketRateHints` in `useConvertedExpenses`), so the trip total equals what left the bank minus what came back. Leftover: kept (spare forex another trip can take), converted back (loss is a spend, a gain a negative-amount spend) or written off. Spends a pocket creates have `source: "forex"` and open the pocket sheet, not the form. Pockets are private: the pocket holds `spendIds` (expenses carry nothing, so shared trips never see it) and is backed up as sync kind `pocket`; new sync kinds go in their own push batches (`NEWER_KINDS`) so an older server can't block the backup. Read-only on Free.
- **Recurring spends** (Plus): rules in `recurringStore` (backed up as sync kind `recurring`) are added by `runRecurring` on launch and return (`useRecurringRunner`), with ids per rule and day; only the phone that set a rule up adds it, and rules pause on the free plan. Dates are pure in `utils/recurring.ts`.
- **Receipts**: photos come from the system picker and are read on the phone by `@/modules/ocr` (`expo-text-extractor`: ML Kit / Apple Vision; optional native module, so older builds show an update prompt); `utils/receiptText.ts` guesses total, shop, date and items. Pro's split by item sends only the text to online AI (task `receiptItems`).
- **Import from Splitwise / Settle Up** (`ImportFromAppSheet`, free): CSV read on the phone (UTF-8 or UTF-16), parsed in `utils/importFormats.ts` and turned into spends/payments or carried-over balances in `utils/importBuild.ts`; `externalId` keeps re-imports from duplicating.
- **AI tab context**: each trip, group, the money Overview and General has its own chat (conversation key = context id). The default is the active trip, else the group with the latest activity, else General (`utils/chatContextChoice.ts`, pure); the header "About" picker (`aiContextStore`) never changes the active trip and resets when you leave the tab. `loadChatSnapshot` builds that context's money facts (trip facts plus balances, group totals/your share/balances, or the Overview), all computed by the app.
- **Local AI**: llama.rn, managed by `src/modules/ai/local/localModelService.ts` (features use `aiRuntime`). Models download from our R2 models bucket (`EXPO_PUBLIC_AI_MODELS_URL`, `<revision>/<file>`, filled by `scripts/mirror-ai-models.mjs`), or from Hugging Face when it's unset; each file is checked against its sha256. All completions go through its internal queue, and `release()` is safe to call at any time.
- **Splits**: `Expense.paidBy` (or `Expense.payers` when several people paid; amounts add up to the total) / `Expense.shares` (person ids: `SELF_ID` or a companion name) and `Settlement` records in the expenses store. Splits are equal, percent or custom (all free); `Expense.split` stores the mode and percents so editing reopens it the same way, while balances only use `shares`. Split math, balances and debt simplification are pure functions in `features/expenses/utils/split.ts`; amounts are handled in currency minor units.
- **Voice expenses**: `/voice-expense` (`VoiceExpenseScreen`) uses on-device speech only (`useSpeechCapture`: Android 13+ on-device recognizer, iOS `requiresOnDeviceRecognition`; no network fallback). The model only extracts fields (`aiService.extractVoiceExpense`, JSON schema; the transcript text goes online when online AI is in use, never audio); `interpretVoiceExtraction` resolves names and does no arithmetic by the model. Voice needs some AI route (on-device model or online AI). The route is the one exception to `LockGate`: it works while locked and must never show the ledger or balances, or change the trip (no adding companions while locked).
- **Safety tab and circle**: `SafetyScreen` is a full-screen map (you and people sharing with you) with a floating hold-to-SOS button and a fixed glass panel: live cards for a running safe-arrival timer (the check-in) or share, the Share location / Safe-arrival timer / Call tiles (each opens a sheet), the circle row, and a banner only while a phone setting needs fixing (`ReadinessSheet`). The circle (`/circle`, `useCircle`, merge logic in `features/location-sharing/utils/circle.ts`) is the user's `contactLinks`, invites and incoming shares in one list; accepted people get SOS / missed-timer pushes. Who sees you is per person through `setSharePaused`, chosen in `ShareLocationSheet`. There are no share modes in the UI: shares start in normal and the background task switches to low at ≤20 % battery and back at 30 % (`batteryMode`); emergency mode is for SOS only.
- **SOS**: alerts are push-only, to the circle (`alertContactsSos`; while offline the call stays queued and the screen updates when it lands). Apps can't send SMS silently (no `SEND_SMS` on Play, none on iOS), so the SMS composer path (`composeSms` in `sosService`, `smsFallbackStorage`, `SmsTemplatesSheet`, phone `emergencyContactsStorage`, `TrustedContactsEditor`) is kept but not used by the UI until a server SMS provider (e.g. Twilio) is added. The SOS widget opens `nomadsafe://sos?trigger=widget&t=<token>`, which `+native-intent` turns into a request in `quickSosStore`; the Safety tab then runs the same 5 s cancel countdown as the hold button. `<token>` is a random per-install secret (`features/widget/widgetToken.ts`, encrypted MMKV); links without it (e.g. from other apps) only open the Safety tab. Voice widget links carry the same token; without it `+native-intent` drops `autostart` and `source=widget`, so other apps can't start the mic on the lock-exempt voice screen. The Safety tab skips `LockGate` only while that countdown or an SOS is on screen.
- **Widgets**: Android uses `react-native-android-widget` (JS handler registered in `index.ts`, reads the stores directly), with a voice expense widget and an SOS widget. Widget files start with `"use no memo"`: the library calls them as plain functions, and React Compiler hooks break them (the widget renders transparent). Picker previews are in `assets/widgets/`. iOS is a Swift WidgetKit target in `targets/widget/` (`@bacons/apple-targets`, iOS 17+; both widgets are in the `WidgetBundle` in `SosWidget.swift`) that reads trip ids/names and the widget link token from the `group.com.pranav.NomadSafe` App Group, written by `features/widget/syncWidgets.ts`. Share nothing but trip ids, names, UI labels and that token there.
- **Analytics**: PostHog (EU), in `@/modules/analytics`. It's off when `EXPO_PUBLIC_POSTHOG_KEY` is unset and in `__DEV__`. Add events to `AnalyticsEvents` and flags to `FeatureFlags` before using them. Event properties are counts, enums and booleans only, never user content or coordinates. Session replay is started and stopped by the app (off while locked). Wrap new maps or sensitive views in `<PrivateView>`.
- **Errors and logs**: PostHog error tracking (JS, Android JVM + NDK, iOS crashes) and PostHog Logs; there is no Sentry. Log through `logger` from `@/modules/logger`, not `console.*`: it prints in dev and sends to PostHog in production, so attributes follow the analytics rules (no user content). `logger.error` also creates an exception. Release builds upload source maps and native symbols through the `posthog-react-native/expo` plugin and need the `POSTHOG_CLI_*` EAS env vars.
- **i18n**: `useLocalization().t` in components and `translate()` from `@/localization/translate` elsewhere. Add strings to `en.json`, and add their translations to the other locale files in `src/localization/translations/` (a missing key falls back to English). `node scripts/check-i18n-keys.mjs` lists keys used in code but missing from `en.json`. Counts use plural variants: `t("ns.key", { count })` picks `ns.key_one` / `ns.key_other`.
- **Units and clock**: show temperatures, distances, rain and durations through `useLocalization()` (`formatTemperature`, `formatDistance`, `formatRain`, `formatApproxDuration`, `formatCompactNumber`; pure logic in `src/utils/units.ts`), and pass its `hour12` to any `Intl.DateTimeFormat` that shows the hour. They follow Settings → Units / Time format (`unitSystem`, `timeFormat`; null follows the phone). Never use Intl's `style: "unit"`, `notation: "compact"` or `timeStyle` with `hour12`: on iOS, Hermes silently converts units ("6,923.939 mi", "28,800 sec") and ignores `hour12`. Stored values stay metric.
- **Perf tiers**: `usePerfTier()` (`src/hooks/usePerfTier.ts`, pure rules in `src/utils/perfTier.ts`) gives high/mid/low from RAM, Android version and low power mode, plus a once-per-session frame-time check on Home. Weaker phones throttle or lower resolution (sign-in sky, globe, recap map); high looks exactly as designed. Continuous shaders compile on first use and tick at about 30 fps (15 on low). Prefer tiering, pausing (`useAnimationsActive`) or throttling over simplifying the look.
- **Hidden tabs** are frozen on both platforms (Android `freezeOnBlur`; iOS through `FreezeWhenBlurred` in the tab route files).
- **React Compiler caveat**: don't render values read from mutable module caches (e.g. the exchange-rate Map); the compiler memoizes them and they never update. Keep rendered values in state or stores.

## Play Store constraints (don't regress)

- Never add `READ_SMS`, `SEND_SMS` or other restricted permissions. They're listed in `android.blockedPermissions`; SOS alerts go out as push notifications.
- Show `BackgroundLocationDisclosure` before any `requestBackgroundPermissionsAsync()`.
- Health Connect is read-only: `READ_STEPS`, `READ_DISTANCE` and `READ_HEALTH_DATA_HISTORY`, declared in the Play Console Health Connect form; never add write or other data types without updating it. HealthKit's entitlement is stripped by `plugins/withHealthKitGate.js` unless `IOS_HEALTHKIT_ENABLED=1`.
- `react-native-blob-util` (a `react-native-pdf` dependency) declares storage and `DOWNLOAD_WITHOUT_NOTIFICATION` permissions; they're in `android.blockedPermissions`, and its own config plugins aren't used.
- Photos only through the system picker (`expo-image-picker` with all its permissions off); `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO` and `READ_MEDIA_VISUAL_USER_SELECTED` are in `android.blockedPermissions`.
- `RECORD_AUDIO` is allowed only for on-device voice entry; never add a network speech fallback.
- `READ_CONTACTS` and `WRITE_SETTINGS` are in `android.blockedPermissions`: nothing asks for contacts (`TrustedContactsEditor` and onboarding's `requestContacts` are unused) and the ticket screen's brightness is per window. Unblock `READ_CONTACTS` only together with a UI that uses it and the data safety form.
- Keep privacy copy truthful. Online AI requests go to OpenRouter and its model provider via Convex (Pro) or the user's own provider (including, for Pro's split by item, the text read from a receipt, never the photo; receipt photos are read on the phone by `@/modules/ocr`); purchases go to RevenueCat; the free plan's ads go through Google AdMob (advertising ID, approximate location, ad interactions; EU/UK consent via UMP first). Account, live location, the trip backup (trips, expenses, settlements, itinerary, forex pockets, past travel added to the passport; not raw imported text), weather lookups (coordinates rounded to ~10 km, forwarded to MET Norway, cached unlinked to the user), exchange-rate lookups (currency codes and dates, forwarded to Frankfurter, cached unlinked to the user), shared trips (visible to their members), check-in end times / SOS times, the plan and monthly AI usage counts (per feature, no content) and push tokens go to Convex; push notification text goes through Expo/FCM/APNs; everything else stays on the device. Don't claim end-to-end encryption. Update the Play data safety form when this changes.
- Account deletion must keep working in the app (Settings) and on the web (`/delete-account`).

## Key Config

- New Architecture only; the React Compiler is enabled; typed routes are enabled.
- Package / bundle IDs: Android `com.pranav.nomadsafe`, iOS `com.pranav.NomadSafe`.
- Push: Android uses FCM via `google-services.json` (FCM v1 key in EAS). iOS push is stripped by `plugins/withoutPushEntitlement.js` unless `IOS_PUSH_ENABLED=1` (needs a paid Apple team + APNs key in EAS).
- `android.allowBackup: false`. R8 minify and resource shrinking are on (keep rules for llama.rn, Nitro, Skia, Expo's headless app loader and Google's consent SDK are in `app.json`; anything loaded by class name needs one).
- Production builds strip `console.log/info/debug` (`babel.config.js`).
- ESLint uses a flat config extending `eslint-config-expo`, plus the module/atoms import boundaries.
- EAS Update code signing is off (signed updates need a paid EAS plan), so `pnpm update:<channel>` publishes unsigned updates. Builds up to versionCode 7 require signed updates and can never take an OTA. To turn signing back on, restore `updates.codeSigningCertificate` (`certs/certificate.pem`, kept in the repo) with `codeSigningMetadata` `{"keyid":"main","alg":"rsa-v1_5-sha256"}` and pass `--private-key-path keys/private-key.pem` (gitignored; keep its backup); that needs a new build.
- React Native Firebase (App Check) is Android-only for now: `react-native.config.js` keeps its pods out of iOS and `plugins/withFirebaseAppCheck.js` applies its config plugins only once `ios.googleServicesFile` exists.
- Android requires Vulkan 1.1 (`plugins/withVulkanRequirement.js`): Skia Graphite has no GL fallback. Release builds refuse cleartext traffic (`plugins/withNetworkSecurity.js`); no certificate pinning.
- App config is static on purpose: `eas build` compares a runtime fingerprint computed locally with the one on EAS, so config must not depend on env vars that differ between them (see `plugins/withLlamaMemoryEntitlements.js`).
